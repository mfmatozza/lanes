## What this shows
- **The ceiling is gone.** I1 fails in every arm C run, so these scenarios can measure a difference.
- **Team context as worded today does not fix it.** In D, bea's agent got a brief at its prompt naming ana's task (for example "Change addOrder in src/db/orders.ts so it takes one object { net: number, total…"). It still wrote against the code it read, which hadn't changed yet. I3's C-versus-D gap (2/3 against 0/3) is within the noise of 3 runs and depends on whether ana's commit landed before bea read the file.
- **The heads-up never fired**, by design: it fires on an edit of a file a teammate touched, and bea's edits were all in new files and `src/routes.ts`. The collision is on a file bea **reads or imports**, not one she edits.
- I2 passes in both arms: a rename that starts after the caller's file is published finds it with grep.

## What would change the result (next experiment, not built)
- A heads-up at **Read** time, or on a write whose imports point at a file a teammate is changing, saying the API there is about to change and how (from the task title).
- Then rerun I1 and I3 in arm D with the same seeds of timing, 3 runs, and only then a larger n.
