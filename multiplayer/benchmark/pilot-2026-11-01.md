# Multiplayer benchmark: pilot results, 1 November 2026

Protocol: [method.md](method.md), published before this run · Status: **pilot**, which checks the harness, not the product claim

## Setup
- **Lanes commit:** `5838533` (branch `feat/multiplayer-shared-context`). Claude Code 2.1.316, model `haiku`.
- **Scenarios** (frozen spike testbed):
  - V2: 4 agents, 2 hot files.
  - H1: 4 agents, cross-cutting features with a rename that another agent's new code calls.
- **Arms:** C is Lanes leases and checkpoints. D is C plus team context.
- **Runs:** 3 per scenario and arm, 12 runs in all. Every run is reported; none was excluded.
- **Cost:** about $0.25 API-equivalent in total, on a subscription.
- **Data:** the raw runs are under `scripts/runner/results/runs/` (git-ignored), from `2026-11-01T17-28-51-048Z-V2-r1` to `2026-11-01T17-32-52-198Z-H1-team-r3`. Each folder holds `summary.json`, `server.jsonl` and every agent stream.
- **Reproduce:** `npm run build && node scripts/runner/run.ts V2 H1 --runs 3`, then the same with `--team`.

## What this shows
- **The harness works.**
  - Arm D really delivers team context: about 1,000 to 2,000 tokens per run, of which 6 to 13 are heads-ups before an edit.
  - Arm C delivers none.
  - All metrics are collected from the raw logs.
- **Team context did no harm in the pilot.**
  - No agent in D stopped to ask its user (the spike v3 failure). The one disruption was in C.
  - Cost and time are the same in both arms, within run-to-run noise.
- **Lanes kept every change in both arms:** no unpublished work and no syntax errors in any run.

## What this does not show
- **That team context helps.**
  - Both arms passed every task, so these scenarios are too easy to separate them (a ceiling effect).
  - With 3 runs per arm, a confidence interval would say nothing, so we report the raw runs instead.
- **Overlap recall and precision.** The runner does not yet record per-write line ranges, so the metric defined in the method can't be computed. It depends on the line ranges now being built (S6.1).
- **Integration conflicts.** These are not measured for arm A or B yet; the pilot ran only C and D.

## Next
1. **Harder scenarios:** add ones where knowing a teammate's intent should change the outcome, such as a rename announced in the team brief before the caller is written, and same-function edits. The goal is to get off the ceiling before the full run.
2. **Overlap metric:** record write line ranges in the runner, so overlap recall and precision can be computed.
3. **Run the full protocol:** at least 3 runs per task with arms A to D. Publish only with this method and the raw data.

**For external use:** the only claim this pilot supports is "in our pilot, team context added no disruption and no lost work". Nothing about productivity.
